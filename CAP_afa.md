## Cases

Below are a few options to ground your project. Your own idea is equally valid, as long as it meets the requirements.

### Case 1: Retrieval-Augmented Generation (RAG)-powered knowledge assistant

**Objective**: Build an assistant that answers from the user's own data (their notes, FAQs, manuals, or educational content) with citations, rather than from the model's general training.

**Key Tools**: `Claude Code`, `Next.js`, `Supabase` (`pgvector`, Auth, `Row Level Security`), `OpenRouter` (a chat model plus `openai/text-embedding-3-small`), `Vercel`.

**Steps**:

1. **Choose the data**:
    - Pick a body of content the assistant should answer from: your own notes, a set of FAQs, product manuals, or educational material.
2. **Scaffold the app**:
    - Direct the agent to set up `Next.js` and `Supabase` with sign-in and per-user `Row Level Security`, so each user sees only their own data.
3. **Ingest the content**:
    - Chunk the documents and embed each chunk into `pgvector`.
    - Use the same embedding model (`openai/text-embedding-3-small`) at ingest and at query time, or retrieval will silently break.
4. **Build the chat**:
    - When the user asks a question, the app embeds it, retrieves the closest chunks, and answers using only those chunks, with citations back to the source.
    - Keep every LLM and embedding call server-side.
5. **Ship and verify**:
    - Deploy to `Vercel` and open the live URL in an incognito window: signed-out visitors should see the sign-in page, not data.
6. **Harden**:
    - Run `/security-scan`, keep every key out of the repo, and disclose that answers are AI-generated.

**Outcome**: A live, authenticated knowledge assistant that answers from the user's own content with citations.

### Case 2: AI automation tool

**Objective**: Pull data from an external service, use an LLM to analyse or summarise it, present the result, and optionally run it on a schedule.

**Key Tools**: `Claude Code`, an external API (e.g. `Google Analytics 4`, a public data or social API), `MCP` servers, `OpenRouter`, the `schedule` skill, `Next.js` and `Supabase`, `Vercel`.

**Steps**:

1. **Pick the job**:
    - Decide what the tool watches and reports on. Example jobs: a Reddit or Hacker News sentiment scanner, a competitor-mention tracker, a `GA4` weekly-report writer, or a cross-platform ad-spend consolidator.
2. **Wire the data source**:
    - Direct the agent to connect to the external API, with the key held server-side; the agent fetches the raw data, using an `MCP` server where one fits.
3. **Add the AI layer**:
    - Have the LLM summarise, classify, or extract the useful signal from the raw data via `OpenRouter`.
4. **Present it**:
    - Build a simple dashboard or report, and save each run to `Supabase` so results build up over time.
5. **Automate (optional)**:
    - Use the `schedule` skill to run the job on a schedule, for example every morning or once a week.
6. **Ship and harden**:
    - Deploy to `Vercel`, run `/security-scan`, and keep all keys server-side.

**Outcome**: A working automation that turns an external data feed into a useful, AI-written summary, on demand or on a schedule.

### Case 3: Smart document search system

**Objective**: Let users upload and semantically search a large set of documents (contracts, research papers, manuals) and summarise the findings.

**Key Tools**: `Claude Code`, `Next.js`, `Supabase` (`pgvector`, Storage, Auth, `Row Level Security`), `OpenRouter` embeddings, `Vercel`.

**Steps**:

1. **Build the upload flow**:
    - Direct the agent to let users upload documents into `Supabase` Storage.
2. **Ingest**:
    - Chunk each document and embed the chunks into `pgvector`.
3. **Semantic search**:
    - A search box returns the most relevant passages by meaning, not just keyword matches, so a search for "termination clause" finds the right passage even when those exact words are absent.
4. **Summarise**:
    - The LLM summarises or answers questions from the retrieved passages via `OpenRouter`.
5. **Ship and harden**:
    - Deploy to `Vercel`, enforce per-user `Row Level Security` so each user sees only their own documents, and run `/security-scan`.

**Outcome**: A live search tool where users upload a large document set and find and summarise information across it by meaning.

> **Note:** This case is search-and-browse first over a large corpus. Case 1 is a conversational assistant. Build Case 1 if you want a chat interface; build this one if you want to search and skim a big collection.

### Case 4: Multi-modal AI application

**Objective**: Combine images (or audio) with text, so the user uploads an image and the app understands it.

**Key Tools**: `Claude Code`, `Next.js`, a vision-capable model via `OpenRouter`, `Supabase` (Storage, Auth, `Row Level Security`), `Vercel`.

**Steps**:

1. **Choose the job**:
    - Pick what the app sees and does. Example jobs: a receipt scanner that categorises spending, a fridge-photo recipe suggester, a whiteboard-photo note extractor, or an image-description accessibility helper.
2. **Build upload**:
    - Let users upload an image into `Supabase` Storage, and store references to the images in the database rather than the raw image data.
3. **Add vision**:
    - Pass the uploaded image to a vision-capable model via `OpenRouter` and use what it sees to drive the result.
4. **Persist per user**:
    - Save each user's images and results with `Row Level Security` so they see only their own.
5. **Ship and harden**:
    - Deploy to `Vercel`, run `/security-scan`, and disclose that the output is AI-generated.

**Outcome**: A live app that understands an uploaded image and turns it into something useful for the user.

### Case 5: SaaS product with subscriptions

**Objective**: Build a small software-as-a-service product with a free and a paid tier, where an AI feature is the paid value.

**Key Tools**: `Claude Code`, `Next.js`, `Supabase` (Auth, `Row Level Security`), `Stripe` (Checkout and Customer Portal, test mode), `OpenRouter`, `Vercel`.

**Steps**:

1. **Design the product**:
    - A landing page, a free tier, and a paid tier that unlocks the AI feature or higher usage limits.
2. **Build the core**:
    - Direct the agent to build authentication and the core AI app with per-user `Row Level Security`.
3. **Add billing**:
    - Wire up `Stripe Checkout` for upgrades and the `Stripe` Customer Portal for managing or cancelling a subscription.
    - Save the user's current plan on their `Supabase` row.
4. **Gate features**:
    - Every paid feature checks the user's plan on the server, not just in the UI, so a free user cannot reach paid features by tampering with the page.
5. **Ship and harden**:
    - Deploy to `Vercel`, keep `Stripe` in test mode, run `/security-scan`, and keep every key server-side.

**Outcome**: A live SaaS product with a working free-and-paid split where the AI feature is the paid value.

### Case 6: Mobile app with an AI feature

**Objective**: Build a cross-platform mobile app with an AI feature, running on a real phone or an emulator.

**Key Tools**: `Claude Code`, `Expo` (`React Native`), `Supabase` (Auth, `Row Level Security`, Realtime), `OpenRouter`, `Expo Go`.

**Steps**:

1. **Choose the app**:
    - Pick a simple app with one clear AI feature. Example apps: a mood or habit journal with an AI weekly reflection, a photo tracker, or a flashcard app with AI-generated cards.
2. **Scaffold with `Expo`**:
    - Direct the agent to set up an `Expo` (`React Native`) app and reuse a `Supabase` backend, with the session persisted so users stay signed in between visits.
3. **Add the AI feature**:
    - Make the AI call server-side via `OpenRouter`.
4. **Sync per user**:
    - Store each user's data with `Row Level Security`, and optionally use `Supabase` Realtime to sync across devices.
5. **Test on device**:
    - Run the app via `Expo Go` on both `iOS` and `Android`, checking the signed-in and signed-out paths. A real phone is ideal, but an emulator is fine.

**Outcome**: A cross-platform mobile app with a working AI feature, running on a real phone or an emulator.

## Evaluation criteria for all cases

1. **Outcome Quality**:
    - Completeness and functionality of the shipped app; it runs, ideally at a live `Vercel` URL, or on a phone or emulator for a mobile app.
    - User interface and interaction quality, where applicable.
    - A clear `README.md`, as described in the Objective.
2. **Learning Application**:
    - Effective use of the course stack: the `Claude Code` director workflow, `Next.js` and `Supabase`, Auth and `Row Level Security`, and deployment.
    - Agentic-engineering practice: a `CLAUDE.md`, at least one skill, slash command, or subagent used, and at least one pull request reviewed before merging.
3. **Security & Compliance**:
    - Secrets kept out of the repo and used server-side only.
    - `Row Level Security` on every table holding user data.
    - A `/security-scan` pass.
    - Where relevant, AI-generated content disclosed (EU AI Act Article 50) and a working "delete my data" route (GDPR).
4. **Presentation**:
    - Clear explanation of the project's purpose, implementation, and impact.
    - Use of SCR (Situation, Complication, Resolution) or SMART (Specific, Measurable, Achievable, Relevant, Time-bound) frameworks.

## Capstone Showcase

After completing your project, you'll present it to the group during your standup, a chance to share what you built, get feedback, and see what your peers created.

**Before your presentation, upload your project to [showcase.turingcollege.com](https://showcase.turingcollege.com/).** This is where everyone can explore and upvote each other's work.

**Format:** 10 minutes to present, followed by 5 minutes for questions.

To give your presentation a clear structure, try to cover these six points:

1. **The problem:** What are you solving, who is it for, and why does it matter?
2. **Your solution:** What did you build? Walk through the stack, the AI feature, and the key tools you directed `Claude Code` to use.
3. **The data:** What data does the app work with, and how did you prepare, store, and secure it?
4. **Evaluation:** How do you know it works? Share how you tested it and what the results were.
5. **Challenges:** What was the hardest problem to get right, and how did you and `Claude Code` solve it?
6. **What's next:** What would you improve or build with more time?

Covering these six points makes for a stronger presentation than a live demo alone.
